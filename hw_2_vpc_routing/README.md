# Домашнее задание №2: Работа с сетевыми ресурсами (Маршрутизация между 3 VPC в Yandex Cloud)

## 1. Цель работы
Создать сетевую инфраструктуру, объединяющую 3 изолированные виртуальные сети (**VPC 1**, **VPC 2**, **VPC 3**), и настроить таблицы маршрутизации так, чтобы:
* Пакеты из **VPC 3** (`10.3.0.0/24`) доходили до **VPC 1** (`10.1.0.0/24`) и **VPC 2** (`10.2.0.0/24`).
* Пакеты между **VPC 1** и **VPC 2** не проходили (изоляция сегментов).

## 2. Архитектура решения (`main.tf`)
Поскольку в Yandex Cloud отсутствует нативный сервис VPC Peering между сетями одного облака, реализована архитектура **Hub-and-Spoke** на базе ВМ-маршрутизатора с тремя сетевыми интерфейсами (`vm-vpc-router`) и статических таблиц маршрутизации (`yandex_vpc_route_table`):
* **`hw2-vpc-1` (`10.1.0.0/24`):** таблица маршрутизации `rt-vpc1` направляет трафик для `10.3.0.0/24` на `next_hop = 10.1.0.254`.
* **`hw2-vpc-2` (`10.2.0.0/24`):** таблица маршрутизации `rt-vpc2` направляет трафик для `10.3.0.0/24` на `next_hop = 10.2.0.254`.
* **`hw2-vpc-3` (`10.3.0.0/24`):** таблица маршрутизации `rt-vpc3` направляет трафик для `10.1.0.0/24` и `10.2.0.0/24` на `next_hop = 10.3.0.254`.
* **Фильтрация трафика (`iptables` на `vm-vpc-router`):** включена маршрутизация пакетов (`net.ipv4.ip_forward=1`), разрешён форвардинг только для трафика с участием `10.3.0.0/24`, политика по умолчанию `FORWARD DROP` блокирует связность `VPC 1 <-> VPC 2`.

## 3. Результаты тестирования (`ping`)
* `10.3.0.10 (VPC 3) -> 10.1.0.10 (VPC 1)`: **0% packet loss (Успешно)**
* `10.3.0.10 (VPC 3) -> 10.2.0.10 (VPC 2)`: **0% packet loss (Успешно)**
* `10.1.0.10 (VPC 1) -> 10.2.0.10 (VPC 2)`: **100% packet loss (Заблокировано)**
