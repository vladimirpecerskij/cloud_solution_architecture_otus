# Домашнее задание №4: Работа с объектным хранилищем и облачной СУБД

## 1. Цель работы
Изучить сервисы хранения данных и управляемые базы данных в **Yandex Cloud**:
* Загрузка и чтение объектов в **Yandex Object Storage (S3)** через CLI.
* Резервное копирование (`backup`) и восстановление (`restore`) кластера **Managed Service for PostgreSQL**.
* Сравнительное нагрузочное тестирование производительности (`fio`) для трёх типов хранилищ: **Network HDD**, **Network SSD** и сетевого объектного хранилища, примонтированного через **s3fs**.

---

## 2. Архитектура стенда (`main.tf`)
* **Object Storage:** бакет `otus-csa-hw4-storage-2026` с доступом по статическим ключам сервисного аккаунта.
* **Managed PostgreSQL 15:** кластер `hw4-pg-cluster` (`s2.micro`, `network-hdd` 10 ГБ) с базой `otus_db` и пользователем `otus_user`.
* **Вычислительный узел (`hw4-bench-vm`):** виртуальная машина Ubuntu 22.04 с тремя точками монтирования:
  * `/mnt/hdd` — дополнительный блочный диск `network-hdd` (10 ГБ, `ext4`).
  * `/mnt/ssd` — дополнительный блочный диск `network-ssd` (10 ГБ, `ext4`).
  * `/mnt/net_s3` — сетевое объектное хранилище `otus-csa-hw4-storage-2026` через `s3fs-fuse`.

---

## 3. Результаты экспериментов и выводы

### 3.1. Работа с Object Storage через CLI (`yc storage s3api`)
* Выполнена загрузка объекта `hw4_test.txt` (`put-object`, получена контрольная сумма `ETag`) и проверка списка объектов (`list-objects`).

### 3.2. Резервное копирование и восстановление Managed PostgreSQL
* Создана резервная копия кластера `hw4-pg-cluster` (`yc managed-postgresql cluster backup`).
* Выполнен сценарий восстановления нового кластера из созданного бэкапа (`yc managed-postgresql cluster restore`).

### 3.3. Сравнение производительности дисков (`fio` 4K random write / sequential write)

| Тип хранилища | Точка монтирования | Характеристики и назначение |
| :--- | :--- | :--- |
| **Network SSD** | `/mnt/ssd` | Максимальный IOPS (~1000–3000+ IOPS на малых томах) и минимальная задержка; оптимально для БД и транзакционных нагрузок. |
| **Network HDD** | `/mnt/hdd` | Базовый IOPS (~100–300 IOPS); оптимально для холодных данных, логов и файловых архивов. |
| **Network Object Storage (s3fs)** | `/mnt/net_s3` | Высокая задержка на мелких случайных операциях (HTTP-запросы к API S3), но неограниченная масштабируемость и высокая пропускная способность при последовательной записи крупных объектов. |
